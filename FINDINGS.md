# Круг «вставил в игру → выгрузил → сверил»

**2026-09-21.** Главная проверка проекта: сгенерированный код вставлен в живую игру,
выгружен обратно и сравнён с замыслом программой, а не глазами.

**Итог: фильтр импортировался, 13 правил из 13.** Игра приняла код и построила из него
рабочий фильтр. Но кое-что она по дороге поменяла, и это важно знать.

## Что сохранилось точно

- Число и порядок правил.
- Видимость каждого правила (`SHOW`, `RECOLOR`, `HIDE_ALL`).
- Цвета подсветки.
- Условия на тип вещи — включая набор из 27 типов в правилах пряток, все до единого.
- Маски редкости, границы силы предмета, флаг кодекса.
- Значение порога совпадения.

## Что игра поменяла

### 1. Имя фильтра заменено

Отправляли `Blazing Scream Warlock Leveling (S15)`, вернулось `Loot Filter #5`.
Игра называет импортированный фильтр по номеру слота. Косметика.

### 2. Длинные имена правил выброшены

Из тринадцати имён уцелело **одно** — `Мифики`, шесть символов. Остальные вернулись
пустыми, включая `Апгрейд кодекса` (15 символов) и
`Blazing Scream Warlock Leveling (S15) · Helm` (44).

Кириллица сама по себе не мешает — мешает длина. Точный предел не измерен.
**Что сделано:** имена правил укорочены (`Древние`, `Кодекс`, `Helm`, `Ring 1, Ring 2`,
`Мусор: ...`, `Талисманы`), название билда из имён убрано.

### 3. Пустой цвет пишется как ноль

У правил без перекраски мы не писали поле цвета, игра пишет `0`. На поведение не влияет.

### 4. Порядок аффиксов внутри условия нормализуется

Игра переставляет id в свой канонический порядок. На поведение не влияет, но означает,
что побайтовое сравнение «до» и «после» для фильтров с аффиксами невозможно в принципе.

### 5. **Часть аффиксов молча выброшена** ← главное

| Правило | отправили | вернулось | выброшено |
|---|---|---|---|
| Helm | 4 | 3 | Maximum Resource |
| Chest Armor | 4 | 2 | Maximum Resource, Wrath Regeneration |
| Pants | 4 | 2 | Wrath Regeneration, Resistance to All Elements |
| Boots | 4 | 3 | Wrath Regeneration |
| Gloves, Amulet, Ring 1, Ring 2 | 4 | 4 | — |

Выбрасываются три конкретных аффикса: **Maximum Resource, Wrath Regeneration,
Resistance to All Elements**.

### Поправка к первой редакции этого файла

Сначала я записал «выбрасываются только на бронеслотах» и стал искать объяснение в
совместимости свойства с типом вещи. **Это была ошибка чтения собственных данных.**
Ни одно уцелевшее правило этих трёх аффиксов вообще не содержало: перчатки, амулет и оба
кольца их не просили. То есть три id выброшены **везде, где встречались**, и никакой
зависимости от типа вещи в данных нет.

Отдельно проверено и отвергнуто: список аффиксов в редакторе правила **не фильтруется** по
выбранному типу вещи — открыв правило штанов, видим полный список из 68 позиций.

### Что на самом деле видно в числах

| Выжили | id |
|---|---|
| Willpower, Attack Speed, Critical Strike Chance, Critical Strike Damage Multiplier, All Damage Multiplier, Maximum Life, Cooldown Reduction, Movement Speed | `0x1BEAB4` … `0x1BEADE` |

| Выброшены | id |
|---|---|
| Maximum Resource | `0x1BFE79` |
| Resistance to All Elements | `0x1BFF38` |
| Wrath Regeneration | `0x26A57C` |

**Все уцелевшие лежат в одном блоке `0x1BEAxx`. Все выброшенные — вне него.**

Важно: эти три id **игра написала сама** — они взяты из её собственного экспорта. То есть
игра их выгружает, но при загрузке обратно не принимает. Это асимметрия экспорта и импорта,
а не ошибка нашего кодировщика.

### Что сказали внешние источники

Ничего. Ни maxroll, ни fextralife, ни форумы Blizzard, ни открытый генератор сообщества,
ни декодеры кодов не описывают выброс аффиксов при импорте. Единственное относящееся к делу
замечание — в справке D4 Filter Forge: *«Any sort that the game does on import is stable»*,
то есть про перестановку они знают, про потерю — нет.

Спецификация формата подтверждает, что у условия на аффиксы два списка: `params1` — сами
аффиксы, `params2` — пары «великих» аффиксов. Второй мы не заполняем, и на выброс он не влияет.

### Готовый опыт, который это закроет

Собран пробный фильтр: **одно правило, все 11 аффиксов, без условия на тип вещи**
(`scratchpad/probe.mjs`). Импортировать его и выгрузить обратно:

- выживут все 11 → дело в соседстве с условием на тип вещи;
- умрут те же три → игра не принимает эти id при импорте, чем бы их ни окружать.

Опыт не доведён: игра перестала откликаться на синтетическое нажатие `Escape`,
и меню не открылось.

**Чем это плохо.** Порог совпадения игра оставляет прежним. Отправили «не меньше 2 из
четырёх», вернулось «не меньше 2 из двух» — правило стало **строже задуманного**, а не мягче.

**Что сделано:** порог по умолчанию снижен с 2 до 1. При пороге 1 выброс аффиксов не может
ужесточить правило: «хотя бы одно из списка» остаётся «хотя бы одним из списка».

## Как повторить проверку

```
node scratchpad/verify.mjs <файл-с-кодом-из-игры>
```

Скрипт заново собирает ожидаемый код из живого билда и показывает расхождения по правилам.
Файл получают так: экспорт в игре кладёт код в буфер обмена, оттуда `Get-Clipboard -Raw`.
